# Должности и права компании

Назначаемые должности: руководитель сети, руководитель филиала, менеджер, закупщик. В «Команде → Назначить должность и филиал» и в форме филиалов видны четыре должности. Назначение руководителя сети по предыдущему прямому требованию пользователя остаётся доступно только подтверждённому администратору платформы; остальные видят недоступный пункт с объяснением. Это не делает руководителя сети оператором чужих компаний.

Руководитель сети использует существующую роль director: те же полномочия администрирования своей компании, что у company admin (ветки branch_can_manage/branch_can_read, приглашения, назначение филиалов, удаление обычных сотрудников, задания). Межфирменного доступа и is_super_admin не получает. Администратор платформы остаётся отдельным защищённым полномочием. Существующие административные роли автоматически не переназначаются.

Руководитель филиала имеет branch_director в company_branch_members. Текущая привязка к филиалу перекрывает старую широкую роль manager через restrictive RLS. Истории, оценки, сообщения и связанные учебные данные доступны только для текущих сотрудников своего филиала плюс собственная история. Перевод/снятие руководящей должности сразу меняет доступ на сервере.

Менеджер и закупщик — обычные сотрудники с одинаковыми правами. profiles.staff_position различает только название manager/buyer; роль авторизации обоих — employee. Выбор должности не является выбором сценария или тарифа. Не используется старая техническая role=manager, которая в прежних версиях могла давать широкий просмотр. Новое явное назначение обычной должности нормализует profile и membership к employee. Менеджеру/закупщику можно не назначать филиал; руководителю филиала он обязателен.

Миграция supabase/company-positions.sql добавляет staff_position с default manager и защитой от прямого изменения клиентом. Существующие роли, филиалы, тренировки и оценки не переназначаются. Старый candidate RPC не меняет контракт; новый company_position_candidates возвращает точную должность. company_team_positions возвращает только доступную вызывающему область сотрудников. company_branch_context содержит position для меню и главной страницы. Должности команды загружаются с существующим составом через manager-history.js. Старый p_position=employee поддерживается как alias manager.

Назначение: только авторизованный управляющий своей компании либо прежний разрешённый администратор платформы. SQL блокирует чужие компании/филиалы, защищает административные аккаунты, сериализует смену роли с членством и не выдаёт платформенных прав. Прямые изменения профиля/членства не заменяют RPC. Ограничения history RLS не ослабляются и не переписываются.

Проверки: build-company-positions-test.py использует реальные старые branch/network контракты плюс новый SQL. Запускается в отдельном PostgreSQL 16 CI с ROLLBACK: восемь связанных таблиц и сообщения, одинаковый доступ двух обычных должностей, филиальная изоляция, перевод, понижение, должность без филиала, защита сети, межфирменные подмены и самостоятельное повышение. Browser CI проверяет четыре варианта, disabled network для не-администратора, назначение закупщика без филиала, подписи в карточке/меню и мобильный диалог.

До production: зафиксировать точные исходные определения company_branch_context и set_company_position в company-positions-rollback.sql и выполнить backup-only workflow существующих восьми REG.RU assets. После зелёных проверок применить миграцию, проверить grants/RLS, затем стандартный release с повторным бэкапом перед записями и сверкой всех HTTPS-хэшей. Серверные Edge Functions не меняются.

Откат: восстановить frontend из backup релиза и выполнить company-positions-rollback.sql для двух прежних функций. Аддитивную колонку, защитный trigger и read RPC оставить: назначенные названия сохранятся, данные не уничтожаются. Изменения должностей, которые пользователь сам сделал после выпуска, автоматически не отменять.
