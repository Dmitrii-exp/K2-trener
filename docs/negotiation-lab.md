# Разбор реплик, переигрывание и сделка по этапам

Владелец завершённого звонка открывает «История → отчёт → Разобрать реплики». Сервер читает только сохранённый доступный звонок, проверяет владельца и роль по scenario_id. До трёх моментов с точными цитатами (не текстом, придуманным ИИ), влиянием и альтернативой. Руководитель может прочитать готовый разбор, пока исходный звонок доступен по существующей RLS филиала. Создавать и продолжать практику может только её автор.

«Переиграть момент» создаёт независимую попытку: контекст строго до заменяемой реплики, без будущего ответа исходного клиента. До трёх реплик сотрудника, затем сравнительный разбор better/similar/worse/insufficient. Сравнивается первая новая реплика с исходной в одинаковом контексте, отдельно комментируется дальнейший диалог. Нет переноса баллов в исходную тренировку, рейтинг, достижения или статистику. Копирование подсказки не доказывает освоение навыка.

«Тренировки → Сделка по этапам → Открыть практику»: менеджер проходит техника, закупщика, учебное КП, торг и фиксацию условий; закупщик — запрос, сравнение, торг и фиксацию. Текстовый учебный кейс с вымышленными компаниями и явными исходными данными. Учебное КП пишется в диалоге, внешних писем/документов система не отправляет. На этапе максимум 10 пользовательских реплик, переход после отдельной проверки цели. В память переходят только пары реальных дословных цитат обеих сторон. Для техника дополнительно обязателен фактически выданный учебный контакт 88005353555. Переговорное качество оценивает ИИ; проверка цитат обеспечивает происхождение данных, но не доказывает идеальную смысловую оценку модели.

Практика сохраняется отдельно в negotiation_labs. История личных попыток находится внутри практики, без новой вкладки меню. Завершение раньше последнего этапа явно отмечается как неполное. Текущие исходные тренировки, кредиты, задания и оценки не меняются. Доступ к генерации использует тот же серверный subscription/rate gate, что AI-наставник; никакого нового обхода тарифов нет. Пользовательские входы — данные, а не системные команды.

Безопасность: клиенты имеют SELECT-only с RLS текущей компании. Индивидуальные replay/deal доступны только владельцу. Review дополнительно доступен только через актуальную видимость исходной saletrening_sessions, включая ограничения филиала. Запись через три service-only RPC с проверкой владельца/компании. Request ID, payload identity, revision, row lock, cached result и pending lease защищают от дублей, потерянных ответов и устаревших завершений. Ошибка сохраняет состояние до операции; повтор использует тот же запрос. ИИ получает только серверный контекст. Данные не кладутся в localStorage; смена пользователя/компании инвалидирует кэши и поздние ответы.

Миграция supabase/negotiation-lab.sql аддитивна. Новая функция negotiation-lab ранее отсутствовала; существующие функции и их рабочие версии не заменяются. Изменение shared ai-access добавляет только имя нового endpoint в существующий mentor gate, и разворачивается с новой функцией. Перед DB migration проверить отсутствие одноимённых объектов; перед frontend deployment workflow сохраняет backup всех 8 путей, включая новый JS (null, если отсутствует), до любых записей. Проверки remote/public HTTPS сверяют точные хэши, index.html обновляется последним.
