# Филиалы, роли и рейтинг ТОП — спецификация внедрения

Статус: подготовка, без изменений production.

## Роли
- super_admin: действующая защищённая роль; администратор expert-26@yandex.ru после проверки auth user ID.
- network_director: управление филиалами и сотрудниками своей компании, просмотр всей истории.
- branch_director: история и оценки исключительно сотрудников назначенного филиала.
- employee: собственная история; общий список имён и филиалов сотрудников компании.
Не выдавать привилегии по сравнению email на клиенте.

## Данные
- branches(id, company_id, name, created_at, ...), уникальность имени в пределах компании.
- branch_members(company_id, branch_id, user_id, role, ...), проверка company_id и branch_id.
- Приглашения и регистрация должны назначать филиал атомарно, только по серверно подтверждённым полномочиям.
- Перемещение сотрудника не удаляет историю; историческая принадлежность к филиалу требует отдельного решения.
- Не переписывать существующие sessions/scores и правила достижений.

## RLS и API
- До включения branch_director проверить все текущие SELECT-политики для sessions, session_scores, feedback, transcript, messages, realtime tables и API с service_role.
- Проверка права чтения должна опираться на auth.uid(), подтверждённое членство в компании и branch_id, не на переданный клиентом ID.
- Исключить доступ branch_director к чужим историям через RPC, REST и серверные endpoints.
- Публичный рейтинг выдавать через ограниченную проекцию: имя, филиал, количество завершённых текстовых/голосовых тренировок, лучший и средний балл; без transcript, feedback, email.
- Успешность сессии определять по действующей серверной логике, не включать сбойные.

## UI
- Руководитель сети/суперадмин: управление филиалами, назначение руководителей, перемещение сотрудников.
- Руководитель филиала: собственный состав, история и отчёты своего филиала.
- Сотрудник: список команды только с именем и филиалом.
- ТОП: рейтинг сотрудников своей компании по среднему баллу, убывание; при равенстве детерминированный порядок.

## Критерии приёмки
- Изоляция компаний.
- Запрет просмотра чужих сессий и оценок руководителем филиала.
- Невозможность самостоятельного повышения роли и перемещения.
- Текстовые и GPT-Live тренировки, завершение, сохранение, отчёты, достижения и подписки работают как раньше.
- Никаких миграций в production до тестирования и ревью.
