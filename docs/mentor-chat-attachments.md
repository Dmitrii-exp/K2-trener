# AI mentor attachments

Supported JPG/JPEG, PNG, WebP, PDF and UTF-8 TXT, up to 3 files per turn, 5 MiB each. Word documents can be exported to PDF. Photo preview/removal before send; file-only messages get an explicit analysis question. Files are kept in a private Supabase bucket and linked to the original dialogue turn. Existing history/new-chat/retry behavior is preserved. No public URLs or service keys go to the browser.

Uploads use authenticated Storage REST, insert only, unique owner/dialogue/object paths. RLS additionally requires a visible current-company dialogue. No update/delete policies prevent replacing an attachment after it is referenced. The service-only claim wrapper validates owned existing objects and includes immutable descriptors in retry identity. Failed/uncertain uploads keep the same object/request IDs in the active page; a lost successful upload may return 409 on retry. Download requires a current authenticated owner.

The server downloads original bytes and validates size, MIME/signature and UTF-8. Images use base64 image_url, PDFs use Chat Completions file parts, TXT is actual extracted text (max 100,000 characters). Documents are user data, never system instructions. Last 20 persisted messages supply follow-up context; maximum 20 MiB of unique file data per AI call. Larger context returns a new-chat instruction. No silent truncation. Existing provider/model configuration is preserved. Encrypted/corrupt PDFs and unsupported provider modalities may return provider errors; never fabricate analysis. Browser/handler tests mock provider responses and do not establish real paid-model quality.
